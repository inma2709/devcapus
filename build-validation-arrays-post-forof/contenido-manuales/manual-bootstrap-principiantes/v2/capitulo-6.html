Personalizar, comprobar y rendir

Bootstrap es una capa base; styles.css contiene la identidad de DevAcademy y se carga después para aprovechar la cascada.

<link rel="stylesheet" href="bootstrap.min.css">
<link rel="stylesheet" href="styles.css">
.hero-devacademy { background:#20123a; }

Cascada, especificidad y variables

Empieza con un selector de componente, no con !important. DevTools explica qué regla gana. Bootstrap expone variables como --bs-primary y --bs-body-bg; puedes redefinirlas en una zona.

.zona-academia { --bs-primary:#6f42c1; --bs-link-color:#552a9b; }

Responsive y accesibilidad

  • Elements: compara reglas Bootstrap y propias.
  • Device toolbar: prueba 375px, 768px y 1280px.
  • Teclado: foco visible y orden lógico.
  • Contenido: headings, labels, alt y contraste son responsabilidad tuya.

Rendimiento con criterio

Bootstrap no siempre ralentiza una web: puede evitar CSS duplicado y un CDN puede aprovechar caché. Un CSS propio grande también pesa. Mide antes de decidir.

Qué observarCómo
Transferencia y cachéNetwork: recarga normal y sin caché.
CSS no utilizadoMore tools → Coverage; registra la interacción.
OrdenBootstrap antes de tu CSS.
@importEvítalo para CSS crítico: retrasa frente a link.

Comprobación final

  1. Compara Bootstrap y tu CSS en Network.
  2. Usa Coverage durante el recorrido de DevAcademy.
  3. Corrige un problema responsive y uno de teclado.

Resultado: decides con mediciones, no por suposiciones.
