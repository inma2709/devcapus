Wireframes y Penpot: del problema al diseño web

Un recorrido progresivo para planificar, diseñar, comprobar y preparar un portfolio profesional antes de escribir HTML y CSS. No presupone experiencia previa y no elimina los conceptos difíciles: los introduce cuando hacen falta.

Diseñar no significa decorar una página. Significa decidir qué construiremos, cómo se organiza y cómo podrá utilizarlo una persona antes de programarlo.

Idea → objetivo → usuario → contenido → arquitectura de información → wireframe → UX → UI → sistema de diseño → responsive → prototipo → desarrollo.

El proyecto de todo el manual es un CV digital / portfolio profesional. Al final tendrás versiones desktop y mobile, arquitectura de capas, sistema visual, layouts, componentes, tokens, prototipo e información suficiente para implementar la web.

Cómo estudiar

Lee un bloque, realiza la práctica antes de mirar otra sección y nombra el resultado en Penpot.

1. Antes de abrir Penpot: decidir antes de construir

Qué es UX y UI

UX (experiencia de usuario) es si una persona entiende y consigue lo que busca. UI (interfaz) es cómo se presentan y controlan esas decisiones: textos, botones, color y espacio. Una UI atractiva no compensa una UX confusa.

Arquitectura, wireframe, mockup y prototipo

La arquitectura ordena contenido; el wireframe prueba estructura sin decoración; el mockup añade apariencia; el prototipo permite probar navegación e interacciones.

Aplicado al CV

Un reclutador llega con poco tiempo. Debe reconocer quién eres, qué haces, ver proyectos y contactarte. Esa prioridad dicta el orden antes que los colores.

PRUEBA TÚ

Escribe una frase para cada punto: objetivo del CV, visitante principal, acción que deseas que haga y tres contenidos imprescindibles.

ERROR FRECUENTE

Abrir HTML o elegir una paleta antes de saber qué información necesita la persona que visita la página.

Autoevaluación

  1. ¿Qué decisión resuelve la arquitectura de información?
  2. ¿Qué probarías con un wireframe que aún no prueba un mockup?
  3. ¿Por qué UX y UI no son sinónimos?
  4. Ordena: prototipo, contenido, idea, desarrollo.
  5. Razona qué perdería tu CV si ocultara los proyectos.

2. Qué es Penpot

Penpot es una herramienta de diseño de interfaces y colaboración. No programa una web terminada ni sustituye HTML, CSS, JavaScript o las decisiones de desarrollo. Sirve para expresar, probar y comunicar el diseño antes y durante la implementación.

Frente a un editor de código

En un editor creas el producto funcional; en Penpot creas una representación y especificaciones. El código de Inspect es una referencia, no una entrega automática de calidad.

Frente a Canva y Figma

Canva prioriza piezas gráficas rápidas. Penpot y Figma son herramientas de diseño de producto/interfaz. Penpot es open source y su Flex Layout y Grid Layout se relacionan directamente con estándares web.

Puede utilizarse online; los equipos también pueden optar por instalación propia (self-hosted) si su organización necesita controlar su infraestructura. Online simplifica acceso y colaboración; en local se asume mantenimiento técnico.

PRUEBA TÚ

Explica qué parte de tu CV resolverías en Penpot y cuál dejarías necesariamente para el desarrollo web.

Recursos para ampliar: Guía oficial de Penpot.

3. Primer contacto con Penpot

El Dashboard organiza equipos, proyectos, archivos y bibliotecas. Al abrir un archivo llegas al Workspace: cada página tiene su propio lienzo o viewport, una zona casi infinita; un Board es un contenedor que representa una pantalla o tamaño concreto.

En el Workspace identifica: barra de herramientas, Pages, Layers, Assets, paletas, Design, Prototype, Inspect, zoom e historial. Las capas son los objetos: Boards, formas, texto, imágenes y grupos.

[CAPTURA RECOMENDADA: Workspace de Penpot con Pages, Layers, toolbar, panel Design, Prototype e Inspect señalados]

  1. Crea un archivo llamado CV-Nombre-Apellido.
  2. Crea la página Wireframes y un Board con la herramienta Board (atajo B).
  3. Añade rectángulo, texto y otra forma; cambia tamaño y posición.
  4. Duplica, oculta, bloquea y renombra cada capa. Usa deshacer/rehacer para comprobar que puedes experimentar.

PRUEBA TÚ

Construye una tarjeta mínima con Board, rectángulo y texto. Pon nombres que describan su función, no su tipo.

4. Organización profesional del archivo

Un archivo ordenado reduce errores y facilita colaboración. El árbol de Layers expresa una jerarquía padre/hijo similar a la estructura que después tendrá el documento web.

ERROR FRECUENTE

Un elemento puede verse encima de un Board sin pertenecerle. Si está fuera en Layers, no hereda su estructura ni se comportará como esperas en un prototipo. “Rectangle 14” y “Text 22” tampoco explican su intención.

PRUEBA TÚ

Ordena y renombra el árbol anterior. Comprueba en Layers que todos los hijos están realmente dentro de CV Desktop.

5. Define el CV antes de diseñar formas

Inventario de contenido no es escribir el texto definitivo: es decidir qué debe existir y su prioridad. Una estructura habitual es Header, Hero, Sobre mí, Tecnologías, Experiencia, Formación, Proyectos, Contacto y Footer; puede cambiar según tu perfil y objetivo.

Nivel esencial

Formula: “Quiero que tipo de visitante entienda que soy perfil y haga acción”.

Nivel avanzado

Redacta una historia de usuario: “Como reclutadora, quiero filtrar rápidamente los proyectos para valorar la experiencia relevante”. Después dibuja su flujo.

PRUEBA TÚ

Crea una tabla con sección, contenido, prioridad (alta/media/baja) y acción asociada. No abras Penpot hasta terminarla.

6. Wireframing desde cero

Un wireframe resuelve jerarquía, agrupación, espacio y lectura. Usa gris, negro y blanco para no confundir decisiones de estructura con decisiones estéticas. Baja fidelidad no significa descuidada: significa deliberadamente simple.

  1. Crea CV Desktop usando un Board de escritorio apropiado.
  2. Dibuja Header: nombre o marca, navegación y contacto.
  3. Dibuja Hero: foto provisional, título profesional, resumen y CTA.
  4. Continúa con secciones de contenido priorizadas: experiencia, proyectos y contacto deben ser localizables.
  5. Añade Footer y verifica ritmo vertical, alineaciones y espacios.

[CAPTURA RECOMENDADA: Board desktop de un CV en baja fidelidad con Header, Hero, Proyectos y Contacto identificados]

RECUERDA

En esta fase no decidas la sombra perfecta ni la fuente definitiva. Pregunta: “¿se entiende qué hay y dónde está?”

RETO

Da a otra persona diez segundos para mirar el wireframe. Debe señalar quién eres, un proyecto y cómo contactarte.

7. Responsive: rediseñar prioridades, no encoger desktop

Responsive es que la interfaz sigue siendo útil según el viewport, la zona visible del navegador. Mobile first propone resolver primero la restricción más fuerte y añadir espacio después. Un breakpoint responde a una necesidad del contenido, no a un número mágico.

Desktop

Hero: texto | fotografía. Proyectos: [1] [2] [3].

Mobile

Fotografía, texto y botones en columna. Proyectos: [1], [2], [3]. La navegación puede pasar a un control de menú, que debe ser comprensible y accesible.

ERROR FRECUENTE

Hacer el diseño desktop y reducirlo proporcionalmente: provoca textos minúsculos, botones difíciles de tocar y prioridades confusas.

PRUEBA TÚ

Duplica el wireframe como CV Mobile. Cambia orden, columnas y navegación; no limites tu trabajo a cambiar el ancho.

8. Diseño visual / UI

Cuando la estructura funciona, crea un sistema visual: color principal, texto, texto secundario, fondo y superficie; estilos H1/H2/H3/cuerpo/pequeño; y una escala de espacios como 8, 16, 24, 32, 48 y 64. Las escalas evitan decisiones aleatorias.

Tipografía y lectura

La jerarquía resulta de tamaño, peso, altura de línea, contraste y espacio, no solo de “hacer algo grande”. Limita el ancho de líneas largas.

Color e imágenes

Comprueba contraste; no uses solo color para comunicar estado. Las imágenes deben aportar información o atmósfera, no rellenar.

ERROR FRECUENTE

Veinte tamaños de fuente, espaciados aleatorios y color antes de haber resuelto la estructura.

PRUEBA TÚ

Define cinco colores, cinco estilos tipográficos y seis valores de espacio. Aplica solo esos valores al CV.

9. Flex Layout: relaciones en una dimensión

Flex Layout organiza hijos en una fila o columna y adapta la distribución al contenido. Resuelve el problema de tener que mover elementos manualmente cuando cambia un texto, por ejemplo un botón que pasa de “Contactar” a “Ponte en contacto conmigo”.

PenpotConcepto CSSPara qué sirve
Flex Layoutdisplay:flexCrear un contenedor flexible
Directionflex-directionFila o columna
Gap / Paddinggap / paddingSeparar hijos / dar aire interior
Align / Justifyalign-items / justify-contentAlinear en ejes cruzado y principal
Wrapflex-wrapPermitir más líneas
  1. Crea un texto “Contactar” y aplícale un contenedor Flex con padding y gap.
  2. Prueba textos de diferente longitud; el contenedor debe ajustarse con sizing fit, no con ancho corregido a mano.
  3. Construye un grupo de botones, una navegación, tags de tecnologías y el Header.
  4. Comprueba qué hijo es estático y cuál debería ser absoluto; lo absoluto sale del flujo.

ERROR FRECUENTE

Mover manualmente elementos que deberían estar en flujo o usar grupos cuando se necesita un layout. Flex no es la respuesta para toda estructura bidimensional.

[CAPTURA RECOMENDADA: Panel Design de un Board con Flex Layout en fila, gap, padding y sizing fit visibles]

PRUEBA TÚ

Haz una fila de cinco tecnologías que permita wrap al reducir el ancho. Explica por qué no basta con usar un grupo.

10. Grid Layout: relaciones en dos dimensiones

Grid organiza filas y columnas al mismo tiempo. Es adecuado para una galería de proyectos en la que las tarjetas se alinean como una matriz. En Penpot puede aplicarse a una capa, grupo, Board o selección; usa contenedor, celdas, áreas, filas, columnas y gap.

Cuándo elegir Flex

Para una relación principalmente lineal: una fila de botones, navegación, lista o contenido de una tarjeta.

Cuándo elegir Grid

Para relaciones entre filas y columnas: cuadrícula de proyectos, panel de métricas o composición con áreas.

  1. Crea el contenedor de proyectos y añade Grid Layout.
  2. Configura tres columnas en desktop, dos en tablet y una en mobile como decisiones separadas.
  3. Coloca tarjetas en auto; prueba manual o áreas solo cuando la composición lo necesite.
  4. Edita filas y columnas; verifica que el contenido conserva su lectura.

ERROR FRECUENTE

Usar Grid para todo o Flex para todo. El criterio es la relación que quieres controlar, no el prestigio de la herramienta.

PRUEBA TÚ

Diseña tres tarjetas de proyecto y escribe por qué su contenedor usa Grid mientras la parte interior de cada tarjeta usa Flex.

11. Componentes: reutilizar con intención

Un componente es una capa o conjunto de capas reutilizable. El componente principal es la fuente de verdad; sus copias o instancias heredan propiedades y pueden tener overrides controlados. Es útil para Button, Card/Project, Tag/Skill, enlace social o Experience Item.

  1. Diseña un botón completo con texto, padding, estados previstos y nombre Button / Primary.
  2. Selecciónalo y crea un componente (la documentación actual indica Ctrl/Cmd + K).
  3. Crea instancias, cambia el texto permitido y verifica que el cambio global del principal se refleja.

ERRORES FRECUENTES

Crear un componente para un elemento único o no crear ninguno cuando algo se repite. En ambos casos se pierde claridad o consistencia.

PRUEBA TÚ

Convierte tres tarjetas de proyecto similares en instancias. Cambia una imagen y un título sin romper el estilo común.

12. Variantes y estados

Las variantes agrupan componentes similares en uno personalizable. Sus propiedades describen dimensiones como Style=Primary/Secondary, Size=Small/Large o State=Default/Hover/Disabled. Los valores deben ser consistentes para conservar overrides al cambiar variante.

IMPORTANTE

Un botón que parece botón no tiene una función definida hasta que decides qué acción inicia, qué estado tiene y cómo responde. Un enlace navega a una URL o sección; un botón desencadena una acción. El diseño debe comunicarlo.

PRUEBA TÚ

Crea variantes de Button para Primary/Secondary y Default/Disabled. Documenta qué debe ocurrir al pulsar cada una.

Recursos para ampliar: Variantes en la documentación oficial.

13. Recursos, bibliotecas y plantillas

Una biblioteca ofrece piezas reutilizables; una plantilla ofrece un punto de partida. Ninguna sustituye la definición del usuario, contenido y flujo. Úsalas para aprender patrones o ganar consistencia, no para ocultar decisiones no tomadas.

Las bibliotecas pueden incluir assets, estilos y componentes compartidos. Una Wireframe Library sirve para componer rápidamente una estructura; después debes validar que encaja con tu CV. En desarrollo, la analogía es: biblioteca Penpot → piezas visuales; Bootstrap → componentes ya implementados en HTML/CSS/JS.

RETO

Toma una sola tarjeta de una biblioteca, adáptala al inventario de tu CV y anota tres decisiones que la plantilla no podía tomar por ti.

14. Design tokens: nombres con significado

Un token es un valor reutilizable con un nombre de propósito. #2563EB dice un valor; color.primary explica una intención. Los tokens pueden representar color, tipografía, espacio, sombra, radio y dimensiones, y actúan como fuente compartida de consistencia.

Token en diseñoPosible propiedad CSS
color.primary--color-primary
spacing.md--spacing-md
radius.card--radius-card

NIVEL AVANZADO

Penpot usa el formato de Design Tokens del W3C DTCG. No necesitas memorizar el formato ahora: entiende que el nombre permite cambiar una regla de forma coherente.

PRUEBA TÚ

Crea tokens para color.primary, color.text, spacing.sm/md/lg y radius.card. Sustituye valores repetidos del CV.

15. Prototipado: probar un flujo, no fingir una aplicación completa

Un prototipo conecta Boards que actúan como pantallas. Una interacción tiene disparador, acción y destino. En el panel Prototype selecciona la capa que debe activar la acción, arrastra la conexión hacia el Board destino y prueba el resultado en View mode. Un flow start se crea al conectar.

  1. Crea Boards CV y Detalle proyecto.
  2. Confirma en Layers que “Ver proyecto” está dentro del Board CV.
  3. Conecta “Ver proyecto” al detalle; añade “Volver” en sentido inverso.
  4. Añade URL externa a LinkedIn, GitHub o la demo solo cuando la opción esté disponible en tu versión.
  5. Define el punto de inicio y ejecuta Play/preview.

ERRORES FRECUENTES

No definir inicio, conectar el elemento equivocado o dejar el botón fuera del Board. Visualmente puede parecer correcto, pero su estructura no lo está.

[CAPTURA RECOMENDADA: Dos Boards conectados en Prototype mode con un botón “Ver proyecto” seleccionado]

PRUEBA TÚ

Haz navegable el flujo CV → detalle de proyecto → CV y pide a alguien que complete el recorrido sin instrucciones.

16. UX y pruebas

Probar no es preguntar “¿te gusta?”. Da una tarea y observa. El test de cinco segundos pregunta qué entendió una persona al ver la pantalla brevemente. Affordance es que un elemento sugiera cómo usarlo; feedback es la respuesta tras una acción; carga cognitiva es el esfuerzo mental que imponemos.

Checklist de prueba:
  • ¿Se entiende quién soy y qué hago?
  • ¿Se localizan proyectos y contacto?
  • ¿Está claro dónde hacer clic y cómo volver?
  • ¿Se conserva el sentido en móvil?

PRUEBA TÚ

Pide a una persona que encuentre un proyecto y tu contacto. No la ayudes; apunta dónde duda y mejora solo tras observar.

17. Accesibilidad desde el diseño

Accesibilidad es que más personas puedan percibir y usar el producto. Comprueba contraste, tamaño y legibilidad del texto, jerarquía, objetivos táctiles generosos, foco visible y que la información no dependa solo del color. Una imagen informativa necesitará un texto alternativo adecuado al implementarla.

CONEXIÓN CON HTML/CSS

El diseño define intención: foco, estados y jerarquía. HTML semántico, alt, teclado y CSS convierten esa intención en experiencia real.

PRUEBA TÚ

Revisa un estado de error del formulario de contacto: añade texto explicativo y un icono o forma; no lo señales solo en rojo.

Recursos para ampliar: WCAG 2.2 Quick Reference (W3C).

18. Inspect: entregar información, no copiar a ciegas

Inspect muestra propiedades, dimensiones, medidas, distancias, tipografía, color, espaciado, recursos exportables y fragmentos de código. Puede activarse desde el Workspace o View mode. Selecciona una capa y pasa sobre otras para ver distancias respecto a ellas o al Board.

ERROR FRECUENTE

Copiar código de Inspect sin entenderlo. El fragmento puede ser una buena referencia de propiedades, pero no resuelve semántica, responsive completo, estados, accesibilidad ni arquitectura del proyecto.

PRUEBA TÚ

Inspecciona una tarjeta y escribe qué valores trasladarías a CSS y qué decisiones seguirían faltando para implementarla.

19. Del diseño a HTML y CSS

El Board no se convierte automáticamente en una web: es un viewport de referencia. La transferencia consiste en reconocer estructura, comportamiento y reglas reutilizables.

RETO

Señala en el CV diseñado qué sería header, nav, main, cada section, una tarjeta article y footer. Justifica una decisión.

20. Proyecto final guiado: tu CV listo para desarrollar

  1. Objetivo y usuario: redacta la frase de intención y la acción principal.
  2. Contenido: crea inventario y prioridades.
  3. Wireframe: construye desktop y mobile con Boards y capas bien nombradas.
  4. Sistema visual: aplica tipografía, color, espaciado y contraste.
  5. Layouts: usa Flex en relaciones lineales y Grid en la sección de proyectos.
  6. Sistema: crea componentes, variantes útiles y tokens básicos.
  7. Prototipo: conecta al menos un proyecto y un regreso; comprueba inicio.
  8. Calidad: realiza una prueba de UX y revisión de accesibilidad.
  9. Handoff: inspecciona y prepara el mapa hacia HTML/CSS.

Entrega final

  • Boards desktop y mobile.
  • Capas ordenadas y nombradas.
  • Paleta, tipografía y escala de espacio.
  • Botones, tarjetas y componentes/instancias.
  • Flex, Grid y tokens aplicados con criterio.
  • Prototipo navegable y revisión de accesibilidad.
  • Documento breve que conecte el diseño con la futura estructura HTML/CSS.

Resultado

Si has seguido el recorrido, sabes pensar qué construir, organizar contenido, crear wireframes desktop y mobile, trabajar con Boards y capas, aplicar Flex y Grid, reutilizar componentes, usar tokens, prototipar, inspeccionar y preparar el paso a HTML/CSS.
