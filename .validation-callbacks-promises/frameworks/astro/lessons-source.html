Astro: de HTML a componentes

Hemos creado páginas HTML, pero repetir la misma navegación y pie en cada archivo es incómodo. Astro permite concentrar HTML repetido en componentes y generar páginas con contenido ya visible.

Son como piezas de Lego: cada componente es un bloque que se puede usar en varias páginas. En este manual aprenderás a crear componentes, un layout y una web multipágina con HTML, CSS y un poco de JavaScript.

Como ya sabes el 80% de una pagina web es HTML. Ese es el poder de Astro, que te permite crear paginas web con HTML y CSS y un poco de JavaScript.

¿Qué es Astro y por qué aprenderlo?

Qué vamos a aprender

Qué es Astro, qué problemas resuelve y cuándo es una buena opción para un proyecto.

El problema: copiar y pegar

Con HTML puedes crear varias páginas sin ninguna herramienta. Pero si index.html, servicios.html y contacto.html tienen la misma navegación y el mismo pie, cada cambio obliga a editar tres archivos. Es fácil olvidar uno.

Astro en una frase

Astro es una herramienta para crear sitios web. Usa componentes para reunir HTML repetido y genera HTML para las páginas. Un componente no es magia: es un archivo que contiene una parte reutilizable de tu interfaz.

Esto no significa que JavaScript sea malo ni que Astro lo elimine: Astro permite no enviarlo cuando no es necesario. React también puede usar renderizado en servidor o generación estática mediante otros frameworks. Google puede indexar contenido generado con JavaScript; tener HTML listo no hace que una página posicione automáticamente.

Rendimiento, SEO y las islas

Al entregar menos JavaScript innecesario, un sitio puede tener buenas condiciones para cargar rápido. Es potencial, no garantía: imágenes pesadas, CSS bloqueante o código excesivo pueden empeorar cualquier web. PageSpeed Insights mide, entre otras señales, LCP (cuándo aparece el contenido principal), INP (respuesta a una interacción) y CLS (saltos inesperados del diseño).

La arquitectura de islas deja estática la mayor parte de la página y activa con JavaScript solo una parte interactiva, por ejemplo un buscador. En este manual no necesitas crear islas.

¿Cuándo elegirlo?

Astro encaja especialmente en documentación, portfolios, blogs y webs corporativas con mucho contenido. Una aplicación donde casi toda la pantalla cambia constantemente —un panel muy interactivo— puede resultar más natural con React.

Práctica guiada

  1. Abre dos páginas HTML de un proyecto anterior.
  2. Marca qué fragmentos copiaste en ambas: navegación, footer o metadatos.
  3. Escribe un cambio que tendrías que repetir hoy.

Ejercicio autónomo

Haz una lista de tres piezas de una web que merecerían convertirse en componentes y explica por qué.

1. Antes de Astro: ¿qué es un framework?

HTML aporta estructura, CSS decide la presentación y JavaScript responde a acciones. En una página pequeña puede bastar con esos tres archivos. Cuando un sitio crece, aparecen menús repetidos, reglas de interfaz repartidas y cambios que hay que aplicar en muchos lugares. Un framework propone una forma organizada de construir: convenciones, componentes y herramientas para resolver problemas repetidos.

Una biblioteca es una herramienta que eliges llamar desde tu código; un framework normalmente marca la estructura general y llama a tus piezas en los lugares previstos. La frontera no siempre es absoluta: React es técnicamente una biblioteca, aunque se estudia junto a los frameworks. No toda web necesita uno: una página informativa muy pequeña puede ser más clara con HTML y CSS directos.

2. Por qué aparecieron los frameworks modernos

Las primeras webs eran principalmente documentos. Después llegaron carritos que recalculan precios, gestores de tareas que actualizan una lista y paneles de administración que muestran datos sin recargar la página. Actualizar el DOM manualmente en cada interacción funciona, pero se vuelve difícil de mantener cuando la interfaz tiene muchos estados. Los frameworks ayudan a dividir la interfaz y a coordinar sus actualizaciones.

Ninguna es superior en todos los casos: la interactividad, el equipo y el tipo de contenido cambian la decisión.

4. Cuándo y por qué aparece Astro

Astro se presentó públicamente en 2021 y publicó su versión estable 1.0 en agosto de 2022. Nació para sitios centrados en contenido —documentación, blogs o webs corporativas— donde enviar una aplicación JavaScript completa para cada página puede no aportar valor. Su enfoque HTML-first busca entregar contenido preparado y añadir JavaScript solo donde sea necesario.

5. Cómo funciona Astro

Un componente es un archivo reutilizable. Durante el build, Astro reúne páginas y componentes y genera HTML. Prerenderizar significa preparar ese HTML antes de que una persona visite la web. El navegador recibe contenido visible; los componentes .astro no necesitan un runtime JavaScript para existir. Cuando hace falta interacción, por ejemplo en un buscador, puedes usar una etiqueta <script> o una isla.

React, Vue y Angular también pueden usar generación estática o renderizado en servidor mediante herramientas adecuadas; la diferencia no es que solo Astro pueda entregar HTML preparado.

6. Rendimiento y SEO

Descargar y ejecutar JavaScript consume red, CPU y tiempo del navegador. Reducir JavaScript innecesario puede mejorar el rendimiento, pero no garantiza nada: una imagen enorme, fuentes lentas o CSS bloqueante también empeoran una página. Google PageSpeed Insights ayuda a observar LCP (cuándo aparece el contenido principal), INP (respuesta a una interacción) y CLS (saltos inesperados del diseño).

HTML preparado puede facilitar el rastreo, pero Astro no garantiza posiciones mejores en Google. El SEO depende también de contenido útil, enlaces, metadatos, accesibilidad y rendimiento real.

8. Cuándo utilizar Astro

Es una buena opción para webs corporativas, portfolios, blogs, documentación técnica, landing pages, catálogos, portales educativos y contenido con interactividad localizada. Considera React, Vue o Angular cuando la mayor parte de la pantalla sea una aplicación que cambia continuamente, como un panel complejo de reservas o administración.

9. Ventajas y límites

  • Ventajas: componentes reutilizables, HTML temprano y JavaScript selectivo.
  • Límites: no sustituye una buena optimización; una aplicación muy interactiva puede requerir más diseño técnico.

10. Actividad de decisión

  1. Una revista digital con artículos, imágenes y un buscador pequeño.
  2. Un tablero colaborativo donde muchas tarjetas se actualizan constantemente.
  3. El sitio corporativo de una clínica con servicios, blog y formulario.

Elige una tecnología para cada caso y justifica qué tipo de interfaz predomina.

Solución razonada

Astro encaja bien en la revista y la clínica porque predomina contenido que puede entregarse como HTML; el buscador puede ser una isla. Para el tablero colaborativo, una solución centrada en React, Vue o Angular puede resultar más natural por la interacción continua y el estado compartido. Son decisiones de contexto, no reglas absolutas.

Resumen

Astro reutiliza estructura con componentes y puede generar HTML anticipadamente. Su objetivo no es prohibir JavaScript, sino usarlo con intención.

Mi primer proyecto Astro

Qué vamos a aprender

Crear, abrir y ejecutar un proyecto Astro, entendiendo qué hace cada comando y dónde vive cada archivo.

Antes de empezar

Necesitas Node.js compatible, npm, una terminal y VS Code. Comprueba Node con node -v. La documentación oficial de Astro recomienda usar su asistente de creación y la extensión oficial de Astro para VS Code.

Asegúrate de que tu versión de Node.js sea compatible con Astro. La versión de Astro utilizada en este manual requiere Node.js 22.22.0 o superior. Recomendamos instalar una versión LTS compatible, como Node.js 24.

Comprueba tu versión de Node.js con node -v.

Crear nuestro primer proyecto Astro

Ahora que tenemos Node.js instalado, vamos a crear nuestro primer proyecto Astro utilizando Visual Studio Code.

Paso 1. Abrir la terminal

Abre Visual Studio Code y selecciona Terminal → Nuevo terminal.

Sitúate en la carpeta donde quieras guardar tus proyectos. Por ejemplo, puedes crear una carpeta llamada proyectos-astro dentro de Documentos.

No necesitamos crear previamente los archivos HTML, CSS o JavaScript. Astro se encargará de preparar la estructura inicial del proyecto.

Paso 2. Ejecutar el asistente de Astro

Escribe el siguiente comando en la terminal: 

npm create astro@latest

Este comando utiliza npm para ejecutar el asistente oficial de creación de proyectos Astro.

El asistente realizará varias preguntas:

  1. Nombre del proyecto: escribe mi-primera-web-astro. Astro creará una carpeta con ese nombre.
  2. Plantilla inicial: selecciona una plantilla básica o de ejemplo para empezar. Las opciones disponibles pueden variar según la versión.
  3. Instalación de dependencias: responde afirmativamente para instalar los paquetes necesarios.
  4. Git: puedes permitir que se inicialice un repositorio o hacerlo posteriormente.

Cuando termine, Astro habrá generado la estructura del proyecto y los archivos necesarios para empezar.

Paso 3. Abrir y ejecutar el proyecto

Si tu proyecto se llama mi-primera-web-astro, entra en su carpeta desde la terminal: 

cd mi-primera-web-astro

Si elegiste otro nombre, utiliza el nombre real de tu carpeta.

Ahora ejecuta: 

npm run dev

Este comando inicia el servidor de desarrollo de Astro. En la terminal debería aparecer una dirección parecida a: 

Local http://localhost:4321/

Abre esa dirección en el navegador para visualizar tu web.

¿Qué significa localhost? Es una dirección que apunta a tu propio ordenador. La web todavía no está publicada en Internet: solamente la estamos ejecutando en nuestro equipo.

Mientras el servidor esté funcionando, Astro detectará los cambios que hagamos en los archivos y actualizará la página durante el desarrollo.

Para detener el servidor, vuelve a la terminal y pulsa Ctrl + C.

Conocer la estructura de carpetas de Astro

Antes de empezar a programar, vamos a entender qué ha creado Astro.

Abre el explorador de archivos de VS Code. Si hemos utilizado una plantilla de ejemplo, encontraremos una estructura parecida a esta: 

mi-primera-web-astro/
│
├── .astro/
├── .vscode/
├── node_modules/
├── public/
│
├── src/
│   ├── assets/
│   ├── components/
│   │   └── Welcome.astro
│   ├── layouts/
│   │   └── Layout.astro
│   └── pages/
│       └── index.astro
│
├── .gitignore
├── AGENTS.md
├── astro.config.mjs
├── package-lock.json
├── package.json
├── README.md
└── tsconfig.json

Esta estructura corresponde a un proyecto creado con una plantilla de ejemplo. Dependiendo de la versión de Astro y de la plantilla seleccionada, algunos archivos o carpetas pueden ser diferentes.

Importante: no necesitamos utilizar todos estos archivos desde el primer momento. Vamos a conocerlos para saber qué función cumplen.

1. La carpeta src: nuestro código fuente

La carpeta src es una de las más importantes. Aquí escribiremos y organizaremos el código de nuestra web.

Dentro encontramos varias carpetas:

src/pages — Las páginas de nuestra web

Esta carpeta contiene los archivos que representan las diferentes páginas del sitio.

Por ejemplo, Astro crea inicialmente: 

src/pages/index.astro

Este archivo corresponde a la página de inicio, que podemos visitar en: 

http://localhost:4321/

Si posteriormente creamos: 

src/pages/contacto.astro

Astro generará una página accesible mediante: 

http://localhost:4321/contacto

Esta es una característica importante de Astro: los archivos de la carpeta pages permiten definir las rutas de nuestra web.

src/components — Componentes reutilizables

Un componente es una parte de la interfaz que podemos utilizar en diferentes páginas.

En la plantilla de ejemplo encontramos: 

src/components/Welcome.astro

Este es un componente que Astro incluye para mostrar contenido de bienvenida.

Más adelante crearemos nuestros propios componentes: 

src/components/Navbar.astro
src/components/Footer.astro

De esta forma podremos escribir la navegación y el pie de página una sola vez y reutilizarlos en todas las páginas que los necesiten.

src/layouts — Estructuras comunes

Esta carpeta contiene los layouts, que son componentes utilizados como plantillas para organizar las páginas.

La plantilla de ejemplo ya puede incluir: 

src/layouts/Layout.astro

Un layout puede contener la estructura común del documento HTML:

  • La declaración del documento.
  • Las etiquetas html, head y body.
  • La navegación compartida.
  • El contenido principal de la página.
  • El pie de página.

Más adelante modificaremos o sustituiremos el layout de ejemplo para crear nuestro propio BaseLayout.astro.

También aprenderemos a utilizar <slot />, la etiqueta que indica dónde debe insertarse el contenido de cada página.

src/assets — Imágenes y otros recursos

Esta carpeta se utiliza habitualmente para guardar imágenes y otros recursos que Astro puede procesar durante la compilación.

Por ejemplo, podemos incorporar imágenes que después utilizaremos desde nuestros componentes.

Astro también permite guardar imágenes directamente en public. La diferencia es que los recursos importados desde src pueden aprovechar las herramientas de procesamiento de Astro.

2. La carpeta public

La carpeta public almacena archivos que queremos servir directamente, sin que Astro los procese como parte del código fuente.

Por ejemplo: 

public/
├── favicon.svg
├── imagenes/
│   └── logo.png
└── documentos/
    └── catalogo.pdf

Un archivo situado en public/imagenes/logo.png se puede utilizar mediante: 

<img src="/imagenes/logo.png"
     alt="Logo de la empresa">

Observa que no escribimos public dentro de la ruta de la imagen.

3. La carpeta node_modules

Esta carpeta contiene los paquetes y dependencias que necesita nuestro proyecto.

Se genera cuando instalamos las dependencias con npm. Puede contener cientos o miles de archivos.

No debemos modificar manualmente los archivos de node_modules.

Tampoco es necesario subir esta carpeta a GitHub. Normalmente está incluida en .gitignore.

Si descargamos el proyecto en otro ordenador, podremos volver a instalar las dependencias ejecutando: 

npm install

4. La carpeta .astro

Esta carpeta contiene información y archivos generados automáticamente por Astro durante el desarrollo.

Puede incluir metadatos y tipos utilizados por las herramientas del proyecto.

No es una carpeta donde escribiremos nuestras páginas ni nuestros componentes.

Generalmente no necesitamos modificarla.

5. La carpeta .vscode

Esta carpeta almacena configuraciones específicas para trabajar con el proyecto en Visual Studio Code.

Puede incluir recomendaciones de extensiones o ajustes para el editor.

No contiene el código principal de nuestra web.

Los archivos de configuración del proyecto

Además de las carpetas, Astro crea varios archivos en la raíz del proyecto.

package.json

Es uno de los archivos más importantes en cualquier proyecto que utiliza Node.js y npm.

Define información del proyecto, sus dependencias y los comandos disponibles.

Por ejemplo, contiene scripts que nos permiten ejecutar: 

npm run dev
npm run build
npm run preview

dev inicia el servidor de desarrollo. build genera la versión de producción. preview permite revisar localmente el resultado generado.

package-lock.json

Registra las versiones concretas de las dependencias instaladas por npm y facilita reproducir una instalación de forma consistente.

Normalmente npm se encarga de actualizar este archivo. No necesitamos editarlo manualmente.

astro.config.mjs

Es el archivo de configuración de Astro.

Permite definir opciones del proyecto e incorporar determinadas integraciones.

En este curso utilizaremos la configuración inicial sin realizar cambios avanzados.

tsconfig.json

Es un archivo de configuración relacionado con TypeScript y las herramientas de análisis de código.

Aunque escribamos JavaScript en nuestro proyecto, Astro puede incluir este archivo para configurar el entorno y proporcionar ayuda al editor.

No necesitamos aprender TypeScript para completar este manual.

.gitignore

Este archivo indica a Git qué archivos y carpetas debe ignorar.

Por ejemplo, normalmente evitamos subir node_modules al repositorio.

Si ya has trabajado con Git y GitHub, seguramente reconocerás su utilidad.

README.md

Es un archivo de documentación escrito en Markdown.

Normalmente se utiliza para explicar:

  • Qué hace el proyecto.
  • Cómo instalarlo.
  • Cómo ejecutarlo.
  • Qué tecnologías utiliza.

Es especialmente útil cuando compartimos nuestros proyectos mediante GitHub.

AGENTS.md — Instrucciones para agentes de IA

En algunas plantillas o entornos de desarrollo podemos encontrar un archivo llamado AGENTS.md.

Este archivo puede contener instrucciones dirigidas a asistentes de programación con inteligencia artificial, como Codex u otras herramientas compatibles.

Por ejemplo, puede indicar:

  • Cómo está organizado el proyecto.
  • Qué convenciones de código debemos seguir.
  • Qué comandos deben utilizarse para realizar pruebas.
  • Qué archivos deben evitarse o conservarse.

AGENTS.md no es un archivo obligatorio de Astro ni es necesario para que nuestra web funcione.

Es un documento auxiliar de instrucciones. Su presencia depende de la plantilla o del entorno con el que hayamos creado el proyecto.

En este manual no necesitamos modificarlo, pero conviene saber para qué sirve.

¿Qué archivos utilizaremos realmente?

Aunque Astro crea muchos archivos y carpetas, en esta primera práctica vamos a trabajar principalmente con los siguientes: 

src/
├── components/
│   ├── Navbar.astro
│   └── Footer.astro
├── layouts/
│   └── BaseLayout.astro
├── pages/
│   ├── index.astro
│   ├── servicios.astro
│   └── contacto.astro
└── styles/
    └── global.css

Algunos de estos archivos y carpetas todavía no existen. Los crearemos progresivamente durante las próximas lecciones.

Nuestro objetivo es conseguir que las tres páginas compartan la misma navegación, el mismo footer y el mismo layout sin duplicar su código.

Guía operativa completa

Herramientas necesarias

Node.js ejecuta las herramientas de Astro fuera del navegador. npm, incluido con Node, descarga dependencias: paquetes que el proyecto necesita. VS Code sirve para editar la carpeta y su terminal acepta comandos; ábrela con Terminal → Nuevo terminal.

Comprueba Node.js y npm

node -v
npm -v

Astro exige una versión compatible de Node. La documentación oficial actual indica Node 22.22.0 o superior y no admite versiones impares como Node 23; para el curso recomendamos Node 24 LTS. Si la terminal dice que node o npm no se reconoce, instala una LTS compatible y reinicia VS Code. El requisito puede cambiar entre versiones: consulta siempre la documentación oficial.

Crea el proyecto

Abre una carpeta donde guardes proyectos personales, no dentro de otro proyecto, y ejecuta:

npm create astro@latest

El asistente creará la carpeta. Usa siempre el nombre mi-primera-web-astro; elige una plantilla básica, JavaScript si no usas TypeScript y confirma la instalación de dependencias. Si pregunta por Git, inicializarlo crea un historial local de cambios; es recomendable, pero no es necesario para que Astro funcione.

Ejecuta el servidor

cd mi-primera-web-astro
npm run dev

cd entra en la carpeta. Verás una dirección similar a http://localhost:4321/: localhost es tu ordenador y 4321 es el puerto que usa Astro por defecto. Ábrela en el navegador. Al guardar cambios, el servidor actualiza la vista; para detenerlo usa Ctrl + C. npm run build genera la versión de producción; npm run preview la revisa localmente. Ninguno publica la web.

Entiende la plantilla

Si aparecen src/pages/index.astro, src/layouts/Layout.astro y src/components/Welcome.astro, la página crea la ruta, el componente es una pieza reutilizable y el layout comparte estructura. El recorrido es página → layout → componente → HTML generado. Si tu plantilla usa otros nombres, no es un error.

Primer cambio y primera ruta

Abre src/pages/index.astro, cambia solo el título visible por «Mi primera web con Astro», guarda y comprueba el navegador. Conserva imports y etiquetas que aún no entiendas. Después crea src/pages/prueba.astro:

Abre http://localhost:4321/prueba. El nombre del archivo dentro de src/pages forma la ruta; no necesitas un router manual.

Errores frecuentes

Dependencias no instaladas
Ejecuta npm install dentro de la carpeta del proyecto.
Terminal en carpeta equivocada
Usa cd mi-primera-web-astro y mira la ruta que aparece antes del cursor.
Puerto ocupado
Detén otro servidor con Ctrl + C o usa la URL alternativa que muestre Astro.
Ruta 404
Comprueba que el archivo está en src/pages, tiene extensión .astro y está guardado.

Lección 3 · 60 min

Mi primer componente reutilizable

Qué vamos a aprender

Convertir la navegación y el footer repetidos en dos componentes que cualquier página puede usar.

Del HTML repetido a una pieza reutilizable

Un componente es un archivo con una parte de la interfaz. Si conoces una etiqueta HTML, reconocerás casi todo el código: dentro escribimos HTML normal. Crea estos dos archivos.

Usarlos en una página

En src/pages/index.astro importa los archivos al inicio y úsalo como si fuera una etiqueta propia. La barra entre <Navbar /> indica que no contiene texto ni etiquetas hijas: es una etiqueta de autocierre.

Importar es parecido a decirle a JavaScript qué archivo vas a utilizar. Ahora coloca exactamente <Navbar /> y <Footer /> también en src/pages/servicios.astro. Si cambias el texto de Navbar.astro, lo verás actualizado en ambas páginas.

Práctica guiada

  1. Crea Navbar.astro y pega la navegación.
  2. Crea Footer.astro.
  3. Importa ambos en Inicio y Servicios.
  4. Cambia «Lumen Studio» por tu marca y comprueba las dos rutas.

Ejercicio autónomo

Añade un enlace «Inicio» al Navbar. No copies el HTML en cada página: edita solo el componente.

Resumen

Un componente concentra HTML repetido. Lo importas una vez en cada página y lo colocas con una etiqueta, igual que <Navbar />.

Lección 4 · 55 min

Layouts: una estructura para todas las páginas

Qué vamos a aprender

Evitar repetir doctype, head, body, Navbar y Footer usando un layout.

Un nivel más de reutilización

Los componentes solucionan dos fragmentos, pero las páginas aún comparten el esqueleto del documento. Un layout envuelve el contenido variable de una página.

<slot /> es el hueco reservado. Cuando una página usa BaseLayout, el contenido que escribas entre su apertura y cierre se inserta justo ahí. No es JavaScript del navegador: es una instrucción de Astro al construir la página.

Antes y después

Antes habrías escrito el documento entero y colocado Navbar y Footer. Ahora esta página se centra en su contenido.

Práctica guiada

  1. Crea src/layouts/BaseLayout.astro.
  2. Mueve allí el documento, Navbar y Footer.
  3. Importa el layout en Inicio y Servicios.
  4. Comprueba en el navegador que las dos páginas siguen teniendo navegación y pie.

Ejercicio autónomo

Añade una clase al <main> del layout y aplica un margen desde el CSS global. Observa cómo afecta a todas las páginas.

Resumen

Un layout guarda la estructura común. <slot /> recibe el HTML específico de cada página.
