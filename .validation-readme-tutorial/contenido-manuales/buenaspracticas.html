Buenas prácticas de desarrollo web

Aprende a convertir un HTML que funciona en un proyecto comprensible, accesible, usable y preparado para crecer.

Semántica y Accesibilidad: El Porqué es Más Importante que el Cómo

La maquetación va mucho más allá de la estética. Un buen desarrollador web crea sitios que no solo se ven bien, sino que son **comprensibles y accesibles** para todos. La base de esto es el uso correcto de las etiquetas HTML.

HTML Semántico 📖

Cada etiqueta tiene un propósito y un significado. Utilizar etiquetas como `<header>`, `<nav>`, `<main>`, `<article>`, `<section>` y `<footer>` en lugar de una colección de `<div>` le da una estructura clara a nuestra página. Esto es crucial para:

  • **SEO:** Los motores de búsqueda entienden mejor el contenido.
  • **Accesibilidad:** Los lectores de pantalla guían a los usuarios por la estructura del sitio.
  • **Mantenibilidad:** El código es más legible para otros desarrolladores.

Accesibilidad (A11y) ♿

Un maquetador profesional siempre piensa en el usuario. La **accesibilidad** es un derecho. Aquí tienes algunas prácticas clave:

  • **Etiquetas y `for`/`id`:** Vincula siempre un `<label>` a su `<input>` para que los usuarios puedan interactuar fácilmente con los formularios.
  • **Atributos ARIA:** Usa atributos como `aria-label` o `role` para proporcionar información adicional a las tecnologías de asistencia cuando la semántica nativa no es suficiente.
  • **Texto alternativo en imágenes:** Usa siempre el atributo `alt` en tus imágenes para describir su contenido.

Una web que funciona no siempre está bien construida

Que el navegador muestre una página no garantiza que sea fácil de comprender, utilizar o modificar. Las buenas prácticas consisten en tomar decisiones razonables y consistentes, no en escribir más código.

Funciona: el navegador muestra la página.
Está bien construida: además es semántica, accesible, usable, organizada y fácil de mantener.

Palabras que utilizaremos

  • Usabilidad: facilidad para comprender y utilizar una web.
  • Accesibilidad: construir contenido utilizable por personas con diferentes capacidades o formas de interacción.
  • Mantenibilidad: facilidad para comprender, corregir y modificar un proyecto con el paso del tiempo.
  • Escalabilidad: capacidad de crecer sin perder orden.
  • Refactorizar: mejorar la calidad del código sin cambiar lo que hace.

Semántica: elegir por significado

Antes de elegir una etiqueta, pregunta: ¿qué significa este contenido?

Menos significativo

<div class="titulo">
  Experiencia profesional
</div>

Mejor decisión

<h2>Experiencia profesional</h2>

<div> es un contenedor genérico y no está mal utilizarlo. El problema aparece cuando existe una etiqueta que expresa mejor el significado, por ejemplo una sección con su encabezado o una navegación con <nav>.

Accesibilidad y usabilidad

La accesibilidad permite que más personas utilicen el contenido. La usabilidad hace que resulte comprensible y sencillo utilizarlo. Están relacionadas, pero no son lo mismo.

Poco informativo

<a href="contacto.html">Haz clic aquí</a>

Destino claro

<a href="contacto.html">Contacta conmigo</a>
  • Incluye alt cuando una imagen aporta información.
  • Mantén una jerarquía lógica de encabezados.
  • Relaciona cada campo de formulario con su label.
  • Usa textos claros en enlaces y botones.
Cuando HTML nativo puede expresar correctamente el significado o comportamiento, empieza por HTML nativo.

Un botón como Enviar mensaje suele ser más claro que “Continuar”, aunque el contexto es quien determina la mejor acción.

El código también lo leen personas

La indentación no cambia la semántica del HTML, pero mejora enormemente la legibilidad. Refleja la relación entre elementos padre, hijo y hermano.

Difícil de leer

<header><h1>Mi CV</h1><nav><a href="#perfil">Perfil</a></nav></header>

Claro y ordenado

<header>
  <h1>Mi CV</h1>
  <nav>
    <a href="#perfil">Perfil</a>
  </nav>
</header>

Comentarios con criterio

No comentes lo que el código ya explica. Un comentario es útil cuando aclara una decisión, una limitación o un motivo. También debe revisarse: un comentario desactualizado puede confundir.

<!-- Esta sección se mantiene antes de formación por decisión del diseño del CV -->

Organización, consistencia y código necesario

mi-cv/
├── index.html
├── paginas/
│   └── contacto.html
└── img/
    ├── foto-perfil.webp
    └── proyecto-veterinaria.webp

Evita nombres como foto1.jpg o pagina2.html. Prefiere nombres que expliquen el contenido. No hay una única estructura correcta: elige un criterio comprensible y mantenlo.

Evita anidar contenedores sin motivo. Cada elemento debería tener una razón para existir. Simplificar no significa escribir siempre menos código: significa evitar complejidad que no aporta nada. Más adelante algunos contenedores serán útiles para el diseño.

Mantenibilidad, escalabilidad y reutilización

Haz la prueba de los seis meses: ¿entenderías este proyecto más adelante? ¿Lo entendería otra persona? Si hoy tienes una página y mañana cinco, o pasas de tres a veinte proyectos, la organización debe seguir teniendo sentido. Cuando veas varias experiencias con la misma estructura article + h3 + p, estás detectando un patrón reutilizable.

Rendimiento básico

Utiliza imágenes con un peso y formato adecuados, evita recursos innecesarios y mantén una estructura razonable. Ya conoces las bases sobre imágenes: aquí el criterio es no cargar más de lo necesario.

Actividad · Mejora una web que ya funciona

Refactorizar significa mejorar la organización o la calidad del código sin cambiar lo que debe hacer. Esta actividad se resuelve exclusivamente con HTML.

Versión inicial: detecta problemas antes de modificarla
<!doctype html>
<html lang="es">
<body>
<div><div>Ana García</div><div><a href="contacto.html">Haz clic aquí</a></div></div>
<!-- Título -->
<div><img src="foto1.jpg"><h3>Sobre mí</h3><div>Desarrolladora web.</div></div>
<div><input type="email" placeholder="Correo electrónico"><button>Enviar</button></div>
</body>
</html>

Fase 1 · Detecta

Problema encontrado¿Por qué lo mejorarías?¿Cómo podrías mejorarlo?

Fase 2 · Refactoriza

  • ¿Existe una etiqueta con más significado que este div?
  • ¿La jerarquía de encabezados representa la estructura?
  • ¿Se entiende el enlace fuera de contexto?
  • ¿Qué necesita el alt?
  • ¿El formulario tiene un label?
  • ¿El comentario aporta información útil?

Fase 3 · Compara

Abre ambas versiones. Probablemente se verán parecidas. Aun así habrás mejorado significado, accesibilidad, usabilidad, legibilidad, organización y mantenibilidad.

Antes de dar por terminado un proyecto

□ Semántica y encabezados con sentido.

□ Imágenes, formularios, enlaces y botones accesibles.

□ Navegación y acciones claras.

□ Código indentado y fácil de leer.

□ Archivos, rutas y comentarios comprensibles.

□ Decisiones consistentes y estructura preparada para crecer.

□ Sin recursos ni elementos innecesarios.
