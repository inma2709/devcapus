La guía definitiva para que los alumnos pongan sus proyectos en línea de forma gratuita, dominen el Git Flow profesional y construyan una carta de presentación interactiva e imbatible para las empresas.

¿Por qué tu Portfolio necesita un Hosting Real? 🤔

Cuando buscas trabajo como desarrollador web, enviar un currículum o un archivo de código comprimido en ZIP ya no es suficiente. Las empresas y los reclutadores técnicos quieren ver tus habilidades en acción al instante con un solo clic. Necesitan **"probar tu código"**.

Aquí es donde entra **GitHub Pages**, un servicio de alojamiento de sitios web estáticos provisto directamente por GitHub. Te permite vincular tu repositorio de código de forma 100% gratuita y segura.

💡 El Concepto Técnico: Todo es HTML, CSS y JavaScript

Un sitio desplegado en GitHub Pages no necesita bases de datos dinámicas ni código complejo de servidor PHP/Python. En el fondo, no es más que tus familiares archivos HTML, CSS y un poco de JavaScript cargándose directamente en el navegador del visitante. Cualquier maquetación que funcione de manera local en tu ordenador se ejecutará con la misma velocidad y precisión en el hosting en la nube de GitHub Pages.

Paso a Paso: Del Código Local a Internet 🌐

Para publicar tu primer portfolio o proyecto (como el *Currículum Digital* o la *Landing de Citas*), sigue estos pasos estructurados.

1

Prepara tu estructura de archivos locales

Asegúrate de que tu proyecto cuenta con un archivo principal llamado exactamente index.html en la raíz del proyecto. GitHub Pages busca este archivo de origen exacto para arrancar tu web. Los assets (CSS, imágenes y scripts JS) deben enlazarse de forma correcta mediante rutas relativas (ej. ./css/style.css) en lugar de absolutas.

2

Crea un repositorio público en GitHub

Inicia sesión en tu cuenta de GitHub y haz clic en el botón verde "New" (o "Nuevo"). Asigna un nombre al repositorio (por ejemplo, mi-portfolio-profesional). Es sumamente importante que lo marques como Público, puesto que los planes gratuitos de GitHub Pages requieren visibilidad externa del repositorio para el despliegue automático. Deja vacías las casillas de inicializar con README, .gitignore o licencia.

3

Vincula tu proyecto local mediante Git

Abre tu consola o terminal (Git Bash, CMD o la terminal de VS Code) posicionada en tu carpeta local de archivos del proyecto y ejecuta secuencialmente los siguientes comandos oficiales: 

# 1. Inicializa el repositorio local
git init

# 2. Añade todos tus archivos al área de preparación (Staging Area)
git add .

# 3. Guarda el estado de tus archivos con un comentario inicial descriptivo
git commit -m "feat: mi primer commit de portfolio listo para subir"

# 4. Define tu rama principal de trabajo por defecto como main
git branch -M main

# 5. Vincula tu repositorio local con el remoto de GitHub
git remote add origin https://github.com/TU_USUARIO/TU_REPOSITORIO.git

# 6. Sube los archivos a la nube en GitHub
git push -u origin main
4

Activa el despliegue automático de GitHub Pages

Una vez subido el código, ve a tu repositorio recién creado en el navegador en la plataforma de GitHub:

  1. Haz clic en la pestaña superior derecha con el icono de engranaje llamado "Settings" (Configuración).
  2. En la barra lateral izquierda, localiza y haz clic en el menú "Pages" (Páginas) dentro del bloque de "Code and automation".
  3. En la sección "Build and deployment", en el desplegable de "Source", selecciona la opción "Deploy from a branch".
  4. En el submenú de "Branch" (Rama), selecciona en el primer desplegable la rama main y en la ruta de carpeta selecciona / (root).
  5. Valida la configuración haciendo clic en el botón "Save" (Guardar).
5

¡A disfrutar de tu sitio web público! 🎉

GitHub activará de fondo un proceso automático llamado **Actions** para procesar y desplegar tu sitio. Espera entre unos 30 y 60 segundos y actualiza la página de "Pages". En la sección superior se te mostrará un banner verde con tu URL mundial oficial:

https://tu-usuario-es.github.io/tu-repositorio/

Reglas de Oro del Maquetador Profesional en GitHub Pages 💡

  • 💡 Mayúsculas y minúsculas: Windows es tolerante a diferencias de tipografía, pero los servidores de despliegue de GitHub corren bajo Linux (sensible a capitalizaciones). Un enlace a ./Foto.PNG fallará silenciosamente si la extensión real física del archivo es .png. Escribe todo siempre en minúsculas.
  • ⚡ Evita las rutas locales absolutas: Las referencias del tipo de dirección disco duro C:\MisProyectos\estilo.css o puertos locales fallarán. Todas tus rutas de assets deben ser relativas al documento HTML.
  • 🔄 Mapear actualizaciones al instante: Tu web es un ente vivo. Si cambias el color de fondo en local, solo necesitas comandos ágiles para empujar la modificación en tiempo récord: git add ., git commit -m "mejoras" y git push. Tu portfolio en internet se actualizará en background de manera completamente automatizada.
